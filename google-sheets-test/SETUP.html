تجربة متابعة مهمة واحدة في Google Sheets

الأعمدة تجريبية وقابلة للتغيير لاحقًا. المصدر هو ترياق؛ الشيت يعرض نسخة للمتابعة. تعديل الشيت لا يعدّل ترياق.

الحزمة جاهزة للإعداد، ولم تُنشر على موقعك أو يُجرّب إرسال حي إلى حساب Google. لا يوجد فيها رموز سرية أو بيانات دخول.

1. رفع نسخة التجربة

  1. احتفظ بنسخة موقعك الحالية للرجوع إليها. استخدم نسخة تجريبية من الموقع إن كانت متاحة.
  2. فك ضغط الحزمة. حدّث ملفات الموقع بمحتويات مجلد المشروع، بنفس طريقة رفع تحديثاتك السابقة، مع إبقاء إعدادات Render وSupabase الحالية.
  3. هذه الإضافة لا تحتاج تشغيل ملف SQL جديد، ولا إعادة تشغيل ملف تحديث 3.0.4 إذا كان مطبقًا بالفعل. تعتمد على قاعدة بيانات 3.0.4 المكتملة.
  4. افتح الموقع وحدّث الصفحة. تأكد من ظهور 3.0.5.
  5. سجّل بحساب أدمن، وافتح Admin → Google Sheets — Test. اختر الكورس ثم الشابتر ثم مهمة تجريبية من أحدث دورة. انسخ معرّف المهمة الظاهر؛ ستحتاجه في الخطوة 4.

لا تغيّر حالة مهمة إنتاج فعلية لمجرد الاختبار؛ يمكن اختبار الإرسال اليدوي بحالتها الحالية، أو استخدام مهمة داخل شابتر تجريبي.

2. تجهيز Google Sheet

  1. افتح Google Sheets وأنشئ شيت فارغًا باسم TERYAQ Progress — Test.
  2. من الشيت افتح الإضافات / Extensions → Apps Script.
  3. احذف الكود الافتراضي والصق الكود أسفل هذا القسم كاملًا. إذا طبّقت الكود القديم الذي أرسلته في المحادثة، استبدله بالكامل بهذا الإصدار.
  4. احفظ. من قائمة الدوال بالأعلى اختر setup ثم اضغط Run. اختر حسابك وامنح الصلاحيات التي يطلبها Google لتشغيل السكريبت الخاص بك.
  5. ارجع للشيت؛ سيظهر تبويب Tasks مع الأعمدة.
  6. من المحرر شغّل testConnection. يجب ظهور صف وهمي بمعرّف TEST-001. تكرار التشغيل يجب أن يحدّث نفس الصف.

هذا الاختبار يثبت الكتابة داخل الشيت فقط. اختبار الربط من سيرفر ترياق يأتي لاحقًا.

// Replace the earlier experimental script with this whole file, then redeploy.
const HEADERS = ['معرّف المهمة','الكورس','الشابتر','مجال العمل','المهمة',
  'المنفّذون وأكوادهم','الحالة','تاريخ البداية','موعد التسليم',
  'تاريخ التسليم الفعلي','آخر تحديث','رابط الأداة'];

function setup() {
  const book = SpreadsheetApp.getActiveSpreadsheet();
  const sheet = book.getSheetByName('Tasks') || book.insertSheet('Tasks');
  const props = PropertiesService.getScriptProperties();
  props.setProperty('SHEET_ID', book.getId());
  if (!props.getProperty('SYNC_TOKEN'))
    props.setProperty('SYNC_TOKEN', Utilities.getUuid() + Utilities.getUuid());
  if (!props.getProperty('WEBHOOK_SECRET'))
    props.setProperty('WEBHOOK_SECRET', Utilities.getUuid() + Utilities.getUuid());
  sheet.getRange(1,1,1,HEADERS.length).setValues([HEADERS])
    .setBackground('#408a71').setFontColor('#ffffff').setFontWeight('bold');
  sheet.setFrozenRows(1);
  sheet.setRightToLeft(true);
  sheet.autoResizeColumns(1,HEADERS.length);
}

function doPost(e) {
  try {
    const body = JSON.parse(e.postData.contents);
    const token = PropertiesService.getScriptProperties().getProperty('SYNC_TOKEN');
    if (!token || !body.token || body.token !== token) throw new Error('Unauthorized');
    return jsonResponse(saveTask(body.task, body.observedAt));
  } catch (error) {
    return jsonResponse({ok:false,error:error.message});
  }
}

function saveTask(task, observedAt) {
  if (!task || !task.id || !task.status || !Number.isFinite(observedAt))
    throw new Error('Invalid task payload');
  const lock = LockService.getScriptLock();
  lock.waitLock(20000);
  try {
    const props = PropertiesService.getScriptProperties();
    const key = 'LAST_SYNC_' + task.id;
    if (Number(props.getProperty(key) || 0) > observedAt) return {ok:true,stale:true};
    const sheet = SpreadsheetApp.openById(props.getProperty('SHEET_ID')).getSheetByName('Tasks');
    const last = sheet.getLastRow();
    const ids = last > 1 ? sheet.getRange(2,1,last-1,1).getDisplayValues().flat() : [];
    const index = ids.indexOf(String(task.id));
    const row = index < 0 ? last + 1 : index + 2;
    const labels = {planned:'مخططة',ready:'جاهزة للبدء',in_progress:'قيد التنفيذ',
      in_review:'بانتظار المراجعة',approved:'معتمدة',changes_requested:'بحاجة لتعديل',blocked:'متوقفة'};
    const values = [task.id,task.course,task.chapter,task.area,task.name,task.executors,
      labels[task.status] || task.status,task.startDate,task.dueDate,task.submittedAt,
      new Date(observedAt).toISOString(),task.url].map(value => {
        const text = String(value == null ? '' : value);
        return /^[=+\-@]/.test(text) ? "'" + text : text;
      });
    sheet.getRange(row,1,1,HEADERS.length).setValues([values]);
    SpreadsheetApp.flush();
    props.setProperty(key,String(observedAt));
    return {ok:true};
  } finally { lock.releaseLock(); }
}

function jsonResponse(body) {
  return ContentService.createTextOutput(JSON.stringify(body))
    .setMimeType(ContentService.MimeType.JSON);
}

function testConnection() {
  saveTask({id:'TEST-001',course:'كورس تجريبي',chapter:'Chapter 1',area:'Questions',
    name:'تجربة الربط',executors:'عضو تجريبي — M001',status:'in_review'},Date.now());
}

3. نشر سكريبت Google

  1. من Apps Script اضغط Deploy → New deployment.
  2. اضغط ترس اختيار النوع واختر Web app.
  3. اجعل Execute as: Me، وWho has access: Anyone. إذا حساب المؤسسة لا يتيح Anyone، يلزم السماح به من إدارة الحساب أو اختيار طريقة ربط مختلفة.
  4. اضغط Deploy وانسخ Web app URL المنتهي بـ /exec.
  5. افتح ترس Project Settings في جانب المحرر، ثم Script Properties. انسخ SYNC_TOKEN وWEBHOOK_SECRET كلًا على حدة إلى إعداداته في Supabase بالخطوة التالية. لا ترسلهما في المحادثة.

إذا عدّلت كود Google بعد النشر، افتح Deploy → Manage deployments → Edit، واختر New version ثم Deploy، حتى يستخدم رابط /exec الكود الجديد. لا تنشر الشيت نفسه للعامة.

4. إعداد الدالة في Supabase

  1. افتح مشروع Supabase الخاص بترياق ثم Edge Functions → Secrets. أضف القيم التالية بالضبط.
اسم الإعدادالقيمة
SHEETS_SYNC_ENABLEDtrue للتفعيل. لاحقًا false للإيقاف.
SHEETS_TEST_TASK_IDمعرّف المهمة المنسوخ من صفحة التجربة في ترياق.
SHEETS_WEB_APP_URLرابط Google المنتهي بـ /exec.
SHEETS_SYNC_TOKENقيمة SYNC_TOKEN من Google Script Properties.
SHEETS_WEBHOOK_SECRETقيمة WEBHOOK_SECRET من Google Script Properties؛ تختلف عن SYNC_TOKEN.
TERYAQ_PUBLIC_URLاختياري: رابط موقع ترياق. يعرض رابط الأداة، وليس رابطًا عميقًا لمهمة محددة.
  1. ارجع إلى Edge Functions وأنشئ دالة جديدة عبر المحرر، باسم google-sheets-sync.
  2. استبدل كود index.ts بمحتوى الملف supabase/functions/google-sheets-sync/index.ts الموجود في الحزمة. انشرها عبر Deploy.
  3. في تفاصيل أو إعدادات هذه الدالة فقط، أوقف خيار Verify JWT / Enforce JWT verification. الدالة تطبق بنفسها تحقق حساب الأدمن للطلبات اليدوية والرمز السري لطلبات الـWebhook. لا تغيّر إعدادات الدوال الأخرى.
  4. انسخ رابط الدالة الذي ينتهي بـ /functions/v1/google-sheets-sync.

Supabase يوفر SUPABASE_URL وSUPABASE_SERVICE_ROLE_KEY للدالة على السيرفر. لا تنقل Service Role Key إلى المتصفح أو Google Sheets. لمن يستخدم CLI: الحزمة تتضمن config.toml لهذه الدالة، وأمر النشر هو supabase functions deploy google-sheets-sync --no-verify-jwt.

5. أول إرسال من ترياق

  1. افتح Admin → Google Sheets — Test واختر نفس المهمة.
  2. اضغط فحص الإعدادات. يجب ظهور مفعّل، مكتملة، ومعرّف المهمة الصحيح. هذا يفحص وجود الإعدادات؛ إرسال الخطوة التالية يختبر صلاحيتها فعليًا.
  3. اضغط إرسال الحالة الحالية للشيت.
  4. افتح الشيت وتأكد من ظهور المهمة الفعلية، حالتها وأسماء المنفذين وأكوادهم.
  5. اضغط الإرسال ثانية؛ يجب تحديث نفس الصف. الصف الوهمي TEST-001 مستقل ويمكن حذفه يدويًا.

6. تشغيل التحديث التلقائي

  1. في Supabase افتح Database → Webhooks، وفعّل الميزة إذا طُلب ذلك، ثم Create webhook.
  2. الاسم: teryaq_sheets_single_task_test.
  3. الجدول: public.workflow_tasks.
  4. الأحداث: INSERT وUPDATE فقط.
  5. اختر HTTP Request، والطريقة POST. ضع رابط دالة Supabase المنتهي بـ /functions/v1/google-sheets-sync؛ لا تضع رابط Google هنا.
  6. أضف Header باسم Content-Type وقيمة application/json.
  7. أضف Header باسم x-teryaq-webhook وقيمته نفس SHEETS_WEBHOOK_SECRET.
  8. إذا ظهر Timeout فاجعله 30000 مللي ثانية، ثم احفظ. اترك جسم الحدث الافتراضي الذي يرسله Supabase.
  9. غيّر حالة المهمة التجريبية بإجراء مسموح من داخل ترياق، وانتظر بضع ثوانٍ، ثم راقب الشيت. لا يحتاج فتح صفحة الأدمن باستمرار.
  10. تحقق من مهمة أخرى: لن تُضاف إلى الشيت، لأن السيرفر يسمح بمعرّف المهمة المحددة فقط.

اختيار مهمة التجربة لا يغيّر قواعد انتقال الحالات أو الاعتماد. أحداث الـWebhook تتبع حفظ المهمة؛ الربط يعكس النتيجة فقط.

7. ما الذي تغطيه التجربة؟

  • تحديث الحالة والتواريخ واسم المهمة عند تغيّر صفها في workflow_tasks.
  • أسماء المنفذين تُقرأ عند كل إرسال. تعديل جدول إسناد المنفذين وحده أو اسم الكورس أو بيانات العضو لا يطلق هذا الـWebhook؛ استخدم الإرسال اليدوي لتحديثها خلال التجربة.
  • العمود «آخر تحديث» هو وقت قراءة الحالة للمزامنة، وليس سجلًا تاريخيًا لتغييرات الحالة.
  • في حالة فشل Google تبقى بيانات ترياق محفوظة. لا توجد طابور إعادة محاولة دائم في نسخة التجربة؛ استخدم زر الإرسال اليدوي. لا نعتمد عليها كتقارير إنتاج حتى يكتمل اختبارها.
  • حذف المهمة أو تصفير مساحة العمل لا يحذف صفها من الشيت تلقائيًا في هذه النسخة. احذف الصف التجريبي يدويًا عند الانتهاء.
  • الأعمدة والتبويبات النهائية تُعتمد لاحقًا مع تحديثاتك القادمة.

8. إيقاف التجربة والمشكلات الشائعة

لإيقاف الإرسال: غيّر SHEETS_SYNC_ENABLED إلى false، وأوقف أو احذف Webhook التجريبي. يبقى الشيت كما هو.

المشكلةما تراجعه
قسم الأدمن الجديد غير ظاهرتأكد أنك أدمن وأن إصدار الموقع هو sheets-test.1. أغلق التطبيق وأعد فتحه لتحديث التخزين المؤقت.
فحص الإعدادات يفشلاسم الدالة ونشرها، وحالة تسجيل الدخول، وخيار Verify JWT لهذه الدالة.
زر الإرسال لا يتفعلاكتمال الإعدادات، true للتفعيل، واختيار نفس المهمة المحددة على السيرفر.
فشل الإرسال للشيترابط /exec، نشر أحدث كود Google، صلاحية Anyone، وتطابق SYNC_TOKEN. بعدها أعد الإرسال.
اليدوي يعمل والتلقائي لا يعملرابط Webhook هو رابط Supabase، والجدول والأحداث صحيحان، والـHeader السري مطابق. راجع سجل Webhook.
