# TERYAQ Master Tool v2.6.8 — release instructions

This ZIP contains only the files used by v2.6.8, plus the two new Supabase migrations (016 and 017). It does not include older versioned app assets or earlier release packages. The existing Supabase project must already have migrations 001–015.

1. Confirm the current Supabase project has migrations 001–015. On a test project first, run migrations `016_submission_backup_locations.sql` and `017_course_workflows.sql` in order. Migration 017 adds course tasks, Course Leads, scoped reviewer access, notifications, immutable review evidence, and the default workflow. Test an owner submission, reviewer decision, Course Lead assignment, and admin override before applying 016 and 017 to production.
2. Upload the complete package to the existing Render site, including `index.html`, all five versioned JavaScript/CSS assets (including `workflow.v2.6.8.js`), `sw.js`, `VERSION.json`, vendor files, icons, fonts, and all other assets. Apply the matching migrations before serving the new application because author selections and Course Progress call the new database functions.
3. As an admin, open Archive → Category → Course → Chapter → Content type → Version → a submission. Use **Download all files (ZIP)** to obtain every attached file in form order. Each file gets an ordered numeric prefix, and the status shows fetching and compression progress. A missing or inaccessible file stops the ZIP and reports an error.
4. Check the **Backup Locations** section below the file list. Enter the Google Drive link, hard-disk path/location, and Telegram channel/message details, then use **Save details** for each. The independent checkboxes represent manual confirmation after you have verified each backup. Saving details and downloading the ZIP do not mark any backup location as complete.
5. Reload an installed app once if it still shows an older cached version, and confirm the displayed version is v2.6.8.
6. In Course Progress, an admin selects a course and opens Manage, assigns a Course Lead, and starts a chapter workflow. The Course Lead assigns an owner, reviewer, and author account from the registered users; the author defaults to the owner when selected. The owner uses the linked editor or submission form. A submitted scientific draft enters In Review after server-side account, chapter and version checks. Other template tasks require a synced document snapshot before review; manual checkpoints require a written work note. The assigned reviewer approves or requests changes. Summary shows required checkpoint progress across the entire course, including chapters not yet started. New release cycles and admin overrides require a reason.

The delivered package passed static checks. Its database migration and role transitions have not been executed against the user's live Supabase project in this workspace.
